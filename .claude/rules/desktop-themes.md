# Desktop themes plugin (`ctxline-desktop-themes`)

Theme mod for the desktop app, `displayName` "ctxline themes". Own `version` in its `plugin.json`. Independent of `ctxline-desktop` (no shared code or state).

Keep current: a `desktop-themes/` change that makes anything here wrong → update this file in the same change.

## Files

- `hooks/looks.ts` — `STYLE_IDS`, `DEFAULT_STYLE`; dark + light palette per style via `makeColors`, plus `codeTheme` (Shiki names; untested, Desktop ignores names it doesn't offer).
- `hooks/scenes.ts` — backdrop SVGs, scene id = style id.
- `hooks/register.tsx` — `/ctxtheme`, store, apply.
- `hooks/contour-paths.ts` — generated by `node scripts/themes-contour.js`; never hand-edit.
- `hooks/make-colors.js` + `.d.ts` — verbatim copy from the plugin-authoring skill; never edit, re-copy when the build updates.

## Styles

- Accent matches background: orange `ember`, blue `contour`/`keys`, gold `phoenix`, violet `dusk`, periwinkle `mosaic`.
- `makeColors` `problems`: no line may start `Desktop won't paint` (Desktop drops the whole theme); other lines still paint.
- Not themable via the API (README notes it): permission prompts, terminal pane, Changes/files panel, code block background.

## Scenes

- Drawn by `ui.render` `Backdrop` hook as plain `<Svg>` image, no `isInteractive`: scenes are still, and its sandboxed frame blanks on each source change → flash (desktop/mobile only; another plugin's backdrop → `next`).
- Middle sits under the blurred chat column → highlights go in the side strips.
- No script, no motion (CPU, laptop heat); test-enforced: no `animation`/`@keyframes`. CSS only in the scene's own `<style>`.
- Dark first, light in `@media (prefers-color-scheme: light)`. Hook isn't told the mode; backdrop follows the app's light/dark switch (tested without `isInteractive`); app vs OS mode mismatch untested.
- Each under 131,072 chars (test-enforced).

## `/ctxtheme [<style>|off]`

- Not `/theme` (built-in, refused).
- Choice in `$.store` key `style`, re-applied every `session.start` (theme is display-only; `--resume` brings none back). Unreadable store → default style.
- Throwing `$.theme.set`/`clear` (window can't take themes, e.g. terminal) → not drawn; pick still saved.
- Shown style kept in `$.state` `applied`; the list reads it, so a failed save still lists what's on screen.
- `off` → `$.theme.clear()`, clears any plugin's theme → only on the person's ask.

## Known limits (found by testing, README says so)

- Desktop `/clear` removes the background for that session: it claims a pre-started spare session (`main.log` "spare … claimed"), no `session.start`. Tried, neither works: `command.run` hook on `clear` (never runs), re-setting theme on `session.attach`. New Code session or `/resume` brings it back.
- Theme outlives the plugin: removed without `/ctxtheme off` → app keeps its colors, even after restart.

## Mirrors — update when a style or scene changes

- `docs/assets/themes/<style>.svg` (site `#themes` cards, dark only) — generated: `node --experimental-strip-types scripts/themes-assets.mjs` (Node 22.6+). Never hand-edit; CI regenerates it + `contour-paths.ts` and fails on any diff.
- Not drift-tested: `.t-<style>` palette vars + captions in `docs/index.html` `#themes`, `docs/assets/desktop-themes-preview.jpg` (hand-captured), README "Themes".
